# Present Value — Manual Side-by-Side Test Cases (PV-001 … PV-100)

**Tester setup.** Run PerSense-Web and the legacy DOS Per%Sense side by side and enter the identical scenario in both. Before every case: click **Clear All** on the web Present Value screen (the grids start with 4 blank rows; leftover rows are summed in silently) and reset **Settings** to defaults — Basis **360**, Exact method **NO**, COLA escalation month **Anniversary**, Interest paid in Arrears — unless the case says otherwise. Dates are MM/DD/YYYY. The three rate boxes (True Rate % / Loan Rate % / Yield %) are equivalent: editing one fills the other two — when comparing with DOS, read whichever rate convention the DOS screen is set to (the web **True Rate %** column matches the DOS/help "true rate" convention). To fire a backward solve, leave exactly one cell blank: a row-level target goes in that row's **Value** cell; a screen-level target goes in the **Present Value** box (with Rate or As-of Date blank). Solved cells render green after Calculate; refusals appear in the red error area under the grids. For actuarial cases select the **Per%Sense 1988** life tables — the SSA 2021 tables are new and are NOT expected to match DOS. "Matches DOS" means to the cent (or to DOS's displayed precision where DOS prints whole dollars). Any case marked **[deliberate difference]** touches a documented DOS-vs-port divergence (docs/discrepancies.md / dos_known_frontier.md) — an exact DOS match is NOT expected there; the Expected column says what to check instead.
